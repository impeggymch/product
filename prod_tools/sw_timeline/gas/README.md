# 專案時程管理 — Google 試算表多人版

讓 PM、工程師、使用者用同一個網址一起填寫。資料存在一份 Google 試算表，不需要另外架伺服器。

- **網址分享**：拿到網址的人打開後選自己的名字就能編輯，不需要 Google 帳號。
- **資料位置**：存在 PM 自己的 Google 試算表裡。試算表本身不用分享給其他人。
- **修改紀錄**：每一筆都記錄是誰、何時改的。看「最後更新者」欄，以及「修改紀錄」分頁。
- **同步方式**：每 15 秒自動抓別人的更新。兩人同時改同一個任務的不同欄位，不會互相覆蓋。
- **資料只有一份**：所有專案資料都從 Google 試算表讀取，網頁不內建任何預設資料，瀏覽器也只當暫存。

| 檔案 | 用途 |
|---|---|
| `gas/Code.gs` | 後端程式，貼到 Apps Script，負責讀寫試算表 |
| `index.html` | 網頁（開發資料夾中是 `app/index.html`）。只有這一個網頁檔，本機、Apps Script、GitHub 都用它 |

---

## 一、第一次安裝（約 10 分鐘，PM 做一次）

1. **建立試算表**
   用你的 Google 帳號到 [sheets.new](https://sheets.new) 開一份新的試算表，命名例如「專案時程資料」。

2. **貼上程式**
   1. 在試算表上方選單點「擴充功能 → Apps Script」。
   2. 把左邊 `程式碼.gs` 的內容全部刪掉，貼上 `Code.gs` 的全部內容。
   3. 點左邊「檔案」旁的 **＋ → HTML**，名稱輸入 `Index`（不用打 .html）。
   4. 把預設內容刪掉，貼上網頁檔 `index.html` 的全部內容。
   5. 按 💾 儲存。

3. **初始化工作表**
   1. 上方函式選單選 `setup`，按「執行」。
   2. 第一次執行會要求授權：
      1. 選你的帳號。
      2. 如果出現「Google 尚未驗證這個應用程式」，點「進階 → 前往（不安全）」。這是你自己寫的程式，所以會有這個提示。
      3. 按「允許」。權限只有「查看、編輯試算表」，跟羽球衣服登記頁相同。
   3. 回到試算表，會多出 專案 / 模組 / 功能 / 任務 / 成員 / 設定 / 修改紀錄 幾個分頁。

   > **出現「系統已封鎖這個應用程式」時：**
   > 1. 確認貼上的是最新版 `Code.gs`：搜尋 `getUi`，應該**找不到**。舊版有試算表選單和對話框，需要額外權限，所以會被擋。
   > 2. 還是被封鎖，請確認登入的帳號跟做羽球登記頁時是同一個（點右上角頭像）。瀏覽器同時登入多個 Google 帳號時，建議開無痕視窗只登入那一個。

4. **部署成網頁**
   1. 在 Apps Script 右上角點「部署 → 新增部署作業」。
   2. 齒輪選「網頁應用程式」，設定如下：
      - 說明：隨意填，例如 v1
      - 執行身分：**我**
      - 誰可以存取：**所有人**
   3. 按「部署」，複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。

5. **（選用，建議）設定團隊通行碼**
   1. 打開試算表的「設定」分頁，找到「團隊通行碼」那一列。
   2. 在「內容」欄填一組密碼，例如 `mch2026`。
   3. 之後每個人第一次開網址時要輸入一次。這樣網址外流時，別人也改不了。清空這格就取消通行碼。

6. **匯入現有資料**
   打開網址，點「資料 → 匯入 CSV / JSON」，二選一：
   - 選原本 Excel 匯出的 CSV。
   - 選之前匯出的 JSON 備份。

   如果之前在同一台電腦用過舊版（資料存在瀏覽器的本機版），試算表還是空的時候，畫面上會出現「搬到 Google 試算表」按鈕，按一下就能把舊資料搬進來。

7. **把網址分享給工程師與使用者**
   他們第一次打開會看到「你是誰？」：選自己的名字，或輸入新名字。新名字會自動加進「成員」分頁。

> 如果「誰可以存取」沒有「所有人」這個選項：代表你用的是機構的 Google Workspace 帳號，且管理員限制了對外分享。可以改用個人 Gmail 建立試算表，或請管理員開放。

## （選用）把網頁放在 GitHub

跟羽球衣服登記頁一樣：網頁放在 GitHub Pages，資料仍存在 Google 試算表。好處是網址比較好看，網頁上方也不會有 Google 的提示列。

1. 先完成上面的第 1～4 步，拿到 `…/exec` 部署網址。
2. 用文字編輯器打開 `index.html`，搜尋 `API_URL`，把部署網址貼在 `const API_URL = "";` 的兩個引號中間，存檔。
   （填好之後，在自己電腦直接雙擊這個檔案也能使用，資料一樣存在試算表。）
3. 把這個 `index.html` 上傳到 GitHub repo，並在 repo 的「Settings → Pages」開啟 GitHub Pages。

**注意：**
- **不要上傳原始的 CSV、截圖或 JSON 備份**，裡面有專案的實際時程資料。
- 免費帳號的 GitHub Pages repo 是公開的，任何人都能看到網頁程式碼和部署網址，所以**一定要設定團隊通行碼**。
- 之後若在 Apps Script 建立「新的」部署作業，網址會改變，要記得更新 `API_URL`。用「管理部署作業 → 新版本」更新則網址不變。

## 二、日常使用

- **右上角「☁ 已同步」**：表示資料已存進試算表。
  - **⟳ 儲存中…**：正在上傳。
  - **⚠ 未同步**：連不到 Google。修改會先暫存在這台電腦，恢復連線後自動上傳。
- **右上角「👤 名字」**：切換身分。例如共用電腦時，換成自己的名字。
- **直接在試算表修改**：可以改既有的列，例如日期、狀態、備註，網頁約 15 秒內會更新。
  - 「階段 / 狀態 / 角色」請填網頁上的中文名稱，例如「進行中」「SIT」「工程師」。
  - **新增或刪除任務請用網頁操作**。在試算表直接加的列沒有 ID，網頁會忽略。
- **欄位說明**：
  - 「模組（參考）」「功能（參考）」是系統自動填的，方便閱讀，修改不會生效。
  - 最右邊的 ID 欄不要修改。
  - 你可以在最右邊自己加欄位（例如內部註記），系統不會動到。
- **還原舊資料**：試算表的「檔案 → 版本記錄」可以回到任何時間點。

## 三、之後更新程式

修改了網頁檔 `index.html`（例如新增功能）之後：

1. 有用 Apps Script 網址的話：把新的 `index.html` 貼到 Apps Script 的 `Index` 檔並儲存。若 `Code.gs` 有變，也一起貼上。
2. 有放 GitHub 的話：上傳新的 `index.html`（記得保留 `API_URL` 那一行的網址）。
3. Apps Script 有修改時，發佈新版本：
   1. 「部署 → 管理部署作業」，點鉛筆圖示。
   2. 「版本」選「新版本」，按「部署」。
   3. **網址不會變**，大家重新整理就是新版。

---

## 四、注意事項

- 拿到網址（以及通行碼）的人都能修改全部資料。請不要把網址貼在公開的地方。
- 兩個人在幾秒內改到同一個任務的**同一個欄位**時，以後送出的為準。改不同欄位則兩邊都會保留。
- 網頁是以 PM 的帳號身分讀寫試算表。如果 PM 帳號停用，工具也會停止，需要換人重新部署。
- 網頁的 `API_URL` 沒有填、也不是從 Apps Script 網址打開時，畫面會顯示「尚未連接 Google 試算表」與設定步驟，不能編輯。
- 若「資料 → 匯出」在雲端版無法下載檔案（部分瀏覽器限制），可直接從試算表「檔案 → 下載」取得資料。
